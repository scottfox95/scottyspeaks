# ScottySpeaks (SS2) review — 2026-11-09, Fable 5.2

**Scope and caveats.** Read-only review of HEAD `f709f99` (v0.3.12 + 1 commit). Line numbers are for HEAD. Another session has uncommitted edits in this worktree (main.js, preload.js, tray.js, meeting/screen files), so those files may be shifted a few lines there. Nothing was run on-device and `resources/bin` is not built here, so runtime behaviour in specific apps is marked "suspected". "Certain" means the code path was traced end to end. The screen-recorder window-mode crash and the auto-stop noise-floor bug are excluded as requested.

---

## 1. Executive summary

- **Paste fails by design in many apps, and when it fails the text is not even on the clipboard.** Since `2ff942f`, macOS paste goes through a strict "verified target" helper. It refuses unless the focused element is a native AX text field with an unchanged selection. On refusal the user gets a toast telling them to open History and copy.
- **The failure is undiagnosable.** The helper's reason code is discarded in the renderer, and at the default log level nothing is written to disk (`debugLogger.js:42`).
- **Hotkey-to-microphone latency is self-inflicted.** `startRecording` awaits a process spawn plus AX queries plus three IPC calls before `getUserMedia` (`audioManager.js:440-455`), so first words clip and the start cue is late.
- **The polish server is being stopped by the app's own settings sync.** Every window mount tells main the reasoning provider is "not local", which clears `LOCAL_REASONING_MODEL` and stops llama-server (`useSettings.ts:141`, `ipcHandlers.js:1902-1912`).
- **Recording trust has concrete causes beyond the two already being fixed.** A quiet 2-minute chunk fails a whole local call transcript. A failed call start poisons the call. A CoreML timeout permanently shifts transcripts to the wrong request. A corrupt JSON index stops the app launching.
- **Cross-Mac is manual at every step.** The in-app updater on HEAD has never shipped (released 0.3.12 still has the broken electron-updater one). It checks once per launch, never auto-downloads, and its button lives in a window that is usually hidden. Settings sync is a quit-the-app tarball that overwrites the target.
- **A fresh install is not local-first.** Defaults route dictation to OpenWhispr Cloud, which always errors, and Settings opens on a dead "Account — Disabled" page.
- **Roughly a third of the code is upstream surface Scott cannot reach.** About 1,040 Windows/Linux lines in `clipboard.js`, about 1,160 lines of unreachable cloud/streaming IPC handlers, and about 6,000 lines of orphaned components. They obscure the live paths.

## 6. (a) Paste reliability deep dive

### The actual path today

1. **Hotkey.** Main calls `showDictationPanel()` (`showInactive`, panel type, so focus is not stolen) and sends `toggle-dictation` (`windowManager.js:192-196`; Globe path `main.js:409-479`).
2. **Capture.** The renderer's `startRecording` invokes `recording-target:capture` (`audioManager.js:382-390`). Main spawns a new `macos-recording-target` (`recordingTarget.js:23`). The helper takes the frontmost app and its `AXFocusedUIElement`, and requires a text role, an enabled non-secure field and a readable `AXSelectedTextRange` (`swift:162-178`). It replies `ready` and stays alive holding the element.
3. **Record, transcribe, polish.** Then `safePaste` calls `paste-text` (`ipcHandlers.js:1024`), which applies aliases, dictionary and spoken-form rules and calls `clipboardManager.pasteText`. On darwin that is only `recordingTargets.paste(token, …)` (`clipboard.js:447-453`).
4. **Transaction.** The helper's `performPasteTransaction` (`swift:66-95`) does this:
   - verify
   - snapshot the whole pasteboard
   - verify again
   - write the text
   - verify a third time
   - post ⌘V via CGEvent
   - wait 350 ms
   - restore the pasteboard if `changeCount` is still ours
   
   `verify()` (`swift:182-209`) requires the same focused element, same window, same selection location and length. It re-activates the original app if it is no longer frontmost.
5. **Failure.** Any failure returns `{success:false, reason}`. The clipboard is restored and the renderer shows one generic toast.

The transaction itself is careful. The clipboard snapshot guarded by `changeCount` and the re-activation of the original app are better than most apps and should be kept. The problem is policy: every check is a hard gate, and the fallback is "go to History".

### Every way it pastes nowhere or in the wrong place

Net: the app refuses in a large class of everyday targets, and the user cannot tell which gate fired.

### How best-in-class apps insert text

These are standard techniques. Vendor internals are not public; this is what their observable behaviour is consistent with.

- **Pasteboard plus ⌘V, focus captured at hotkey time.** This is the default for Wispr Flow, Superwhisper and most third-party dictation. It works in every app that supports paste, including Electron, browsers and terminals. Gating is at app level, not field level: frontmost app is the expected one (re-activate if not) and secure input is not enabled (`IsSecureEventInputEnabled()`). The temporary write is tagged with `org.nspasteboard.TransientType` and `ConcealedType` so clipboard managers ignore it. The previous clipboard is restored afterwards.
- **AX insertion** (`kAXSelectedTextAttribute` set, or `AXValue` plus range). No clipboard is involved and the result is verifiable. It is only reliable in native AppKit text views. In web content it bypasses the page's input handlers (React-controlled inputs revert it), and some apps lose undo. Apps that use it restrict it to native fields.
- **CGEvent Unicode typing** (`keyboardSetUnicodeString`, about 20 UTF-16 units per event). Works where paste is blocked. It is slow for long text, and newlines become Return, which sends the message in chat apps. It is a per-app fallback, not a default.
- **macOS Dictation** inserts through the text input system (`NSTextInputClient`), which third parties cannot use without shipping an input method.
- **Verification by read-back.** Where AX is available, read `AXValue`, `AXNumberOfCharacters` or the selection range before and after and confirm the caret advanced by the inserted length. Where it is not, assume success and make recovery one keystroke.
- **Never lose the text.** On any doubt, leave the text on the clipboard and say so. A "paste last transcript" shortcut is standard.

### Recommended layered strategy for SS2

**Principle: checks become signals that choose a strategy and inform the user. Only two things hard-block: secure input, and no frontmost app.**

- **L0 — Capture in main at hotkey time, from a persistent helper.**
  - Replace spawn-per-recording with one long-lived `macos-recording-target` using request ids. This also removes the `osascript` pid capture and the python poller.
  - Capture `{pid, bundleId, element?, window?, selection?, role?, isSecure}` when the hotkey fires in main (`windowManager.createHotkeyCallback`, Globe/right-modifier/mouse/pedal handlers in `main.js`). Do not wait for the renderer.
  - On capture, set `AXManualAccessibility = true` on the app element. Avoid `AXEnhancedUserInterface` as a default because it disturbs window managers.
  - In `audioManager.startRecording`, run capture and `getUserMedia` in parallel. Capture must never delay the mic.

## 8. Cross-Mac consistency

### Updates — evaluation of `src/updater.js`

The approach is sound: GitHub Releases zip, `ditto`, bundle-id and version check, copy-then-swap, install on quit. It has these problems.

1. **Not shipped (certain).** Tag `v0.3.12` contains the electron-updater version, which needs a `latest-mac.yml` that publish never produces. Every installed copy needs one more manual `SS2-Update.command` run before in-app updates can work.
2. **One check per launch (certain).** `checkForUpdatesOnStartup` runs once, 3 s after start (`updater.js:430-441`). A Mac that stays on never sees a release.
3. **No auto-download, and the UI is hidden (certain).** The only affordance is a button in the Control Panel (`ControlPanel.tsx:296-303`), which normally sits in the tray.
4. **Signature check does not pin identity (certain).** `codesign --verify --strict` (`updater.js:299-304`) accepts any validly signed bundle with the same bundle id, including ad-hoc. Verify against the running app's designated requirement (`codesign --verify -R`).
5. **Force-exit after 8 s (certain).** R5 above. Refuse to install while a call or screen recording is active.
6. **Signing identity is a single point of failure (certain logic).** `ensure-signing.js:43-88` silently generates a new identity if `~/.scottyspeaks-signing/identity.p12` is missing. Publishing from a second Mac changes the designated requirement. Every Mac then loses Accessibility, Microphone and Screen Recording grants on update, and paste fails with the generic toast. Check whether the Studio and the laptop hold the same p12.
7. **Publish script (certain).**
   - Bumps `package.json` without committing, and the release targets a HEAD that lacks the bump (`publish-update.js:28-39, 138, 155`).
   - No clean-tree or test gate.
   - Deletes and recreates an existing tag (143).
   - Installs locally before publishing.
8. **`SS2-Update.command` (certain).**
   - Parses JSON with `python3` (56-61), which stock macOS does not have.
   - Compares versions by string inequality (75), so it can "update" to an older build.
   - Runs `rm -rf /Applications/SS2.app` before `ditto` (100-101), so a failed copy leaves no app.

### Settings — what exists

`npm run settings:export` and `settings:import` produce and restore a tarball of `Local Storage`, `transcriptions.db`, `pedal-config.json` and `.env`.
- It needs the repo and Node on the source Mac, and SS2 quit on both.
- It overwrites the target's history rather than merging.
- It carries API keys in plaintext.
- It copies Chromium's LevelDB directory, which is brittle.

It is a migration tool, not sync.

### Simplest reliable design

**Updates.**
- Keep GitHub Releases and the custom updater.
- Check on launch, every 6 h, and on `powerMonitor` resume.
- Auto-download in the background.
- Install on quit. Add a tray item "Restart to update to x.y.z" and an overlay toast.
- Never install while recording.
- Pin the designated requirement.
- Publishing becomes: clean tree, `npm run verify:core`, commit and tag the bump, release.
- Back up the p12 somewhere both dev Macs can read. Make `ensure-signing` fail loudly instead of generating a new identity when a release is being built.
- Medium term, an Apple Developer ID removes the quarantine step and the TCC fragility, and makes standard updaters viable.

**Settings.**
1. **Make main the single owner.** Move portable settings out of localStorage into a main-owned `settings.json`. Dictionary, aliases, snippets, style profiles and style examples stay in SQLite, with a `uuid`, `updated_at` and `deleted` column on each row. This also fixes the four-store drift in §3.
2. **Per-device snapshot files.** Each Mac writes only its own `<syncDir>/<deviceId>.json` (atomic write) containing its records with timestamps and tombstones. Each Mac reads all the others and merges per record, last writer wins. No file is ever written by two machines, so a dumb file-sync service cannot create conflict copies.
3. **Transport is a folder chosen in Settings** (OneDrive, Dropbox, iCloud Drive or Syncthing). Since the work Mac uses a different Apple account, use a provider signed in on both. If the work Mac cannot share any folder, use the same per-device files in a private GitHub repo over HTTPS, with the token in `safeStorage`.
4. **What does not sync.** History and audio, API keys (enter once per Mac, stored with `safeStorage`), mic device id, the Parakeet engine choice, permission caches.
5. **Triggers.** Merge on launch, on window focus, on folder change (`fs.watch`), and after local edits (debounced).
6. **First run.** If a sync folder is picked during onboarding, the Mac is configured before the first dictation. Defaults are local either way.
