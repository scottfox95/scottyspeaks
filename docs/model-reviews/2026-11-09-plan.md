  - The updater checks 15 s after launch and then every 6 h.
  - It downloads in the background, installs when SS2 quits, and shows "SS2 x.y.z is ready" and then "SS2 updated to x.y.z".

## Auto-updates: signing, notarization and the Aravo laptop

- **What works without a Developer ID.** The in-app updater downloads with `fetch`, so the new bundle never gets a quarantine flag and Gatekeeper doesn't re-check it. macOS ties Accessibility, Microphone and Screen Recording grants to the designated requirement (bundle id plus certificate root). Every build signed with the same `identity.p12` therefore keeps its permissions across updates. The new pin enforces exactly that requirement on downloads.
- **What a Developer ID adds.** Notarized builds need no `xattr -dr com.apple.quarantine` on first install. Permissions also survive even if the local p12 is lost. And Squirrel/electron-updater becomes an option. It isn't needed for updates to work.
- **Aravo work laptop:**
  - **First install** still needs the one-time quarantine removal, because the app isn't notarized. If the laptop is MDM-managed with Gatekeeper locked down, or uses a binary allow-list (for example Jamf or Santa), a self-signed app may be blocked outright, and so may a swapped bundle after an update. A Developer ID with notarization is the realistic fix.
  - **Network.** Updates need outbound HTTPS to `api.github.com` and `objects.githubusercontent.com`. A corporate proxy that blocks them makes checks fail quietly, and the app keeps working.
  - **Policy.** Software that updates itself from a personal GitHub repo on a work machine may need IT's OK. That's a question for Aravo, not a technical blocker.
  - **No shared Apple account** is needed for anything above, and none for the sync design in step 12. That's why it uses a folder provider rather than iCloud.
- **Publishing.** Releases come only from `npm run publish` on a Mac holding the same `identity.p12`. A build signed with any other identity is now rejected by the updater on every Mac. That is intended: it protects the permissions.
