# SS2: inspectable voice workflows

Approved intent: user asked to proceed with all worthwhile Voicebox-inspired recommendations from the preceding comparison. This covers all six numbered user-facing items and dictation-priority scheduling. No voice-cloning studio or Electron-to-Tauri migration. Existing worktree and installed 0.2.1 are the baseline.

## Required delivered behavior

1. Replay/repair: dictation history retains original audio under a configurable local retention policy; detail view plays audio, shows raw/final/corrected text and model/cleanup settings, reruns recognition with a chosen available model without speaking again, previews before replacing text, and saves a "This was wrong" correction fixture. User fixtures stay local and do not automatically enter Git or leave the Mac. Expired audio leaves text and a clear unavailable state.
2. Call evidence: recorded/imported call audio can be played within the notebook. Clicking a segment timestamp seeks to the correct take/source and time. Local microphone/system audio and multi-take offsets work. Imported text-only transcripts explain absent audio. Edited transcripts do not falsely claim word alignment. Source audio remains independent of notes.
3. Explicit cleanup: clear controls for filler cleanup, spoken self-corrections and exact wording/technical preservation. Per-capture snapshots and raw-vs-final comparison. No copying Voicebox's split/join paragraph bug or treating model prompts as proof of semantic preservation. Meaningful words, names, numbers, negation, paragraphs and dictated questions remain protected. Distinct visible recording/transcribing/refining/success/error states and recoverable failures.
4. Paste targeting: snapshot intended application/field at recording start; check at paste time. Avoid inserting into a different field after focus moves. Recover transcript with explicit manual-copy path when the original target cannot be verified. Clipboard restoration must not overwrite a newer user copy and should preserve supported rich formats. Existing pedal/hotkey/voice commands continue to work.
5. Selected-call agent access: explicitly grant/revoke individual calls to a local agent interface (MCP stdio preferred). Only approved content is readable, with metadata and timed evidence; no arbitrary path reads, directory indexing, API key access or unapproved calls. Supply concrete configuration for compatible agents, a ready/not-connected status, and a reviewable Markdown handoff for agents that don't use MCP. Agent-produced follow-up/action/requirement drafts stay separate from source transcript and are only filed by the user.
6. Optional local read-aloud: selected notes/transcript/draft text can be spoken, stopped, and configured using installed system voices; optional agent spoken updates are visible, require enabling, and are muted/rejected while a call or dictation recording is active. No cloned voice or automatic external send. Keep spoken output bounded and cancelable.
7. Scheduling: foreground dictation has priority over queued background local call chunks; an active chunk may finish, subsequent chunks yield. Queue is shared across the relevant local engine invocation paths, cancellation removes pending work, errors release capacity, and background processing resumes after foreground work. UI explains waiting and does not claim processing while queued. Local/cloud separation remains explicit.

## Delivery invariants

Preserve existing settings/history/key, raw recordings, user file edits, foot pedal and local/cloud choices. All new component text translated in every locale. IPC sender/path/input checks; no private content logged or published. Tests use synthetic audio/content and no real microphone or cloud uploads. Build/sign/install with rollback backup when engineering checks pass. Validate actual installed UI and distinguish synthetic tests from real-device/provider quality. Do not mark the active goal complete until all seven areas and their verification evidence are delivered.
